# Ledger UX Improvement Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the HitSave Ledger (ledger.hitsave.org) safer and faster for archivists: actions report their outcome, risky actions confirm first, and every package gets its own page.

**Architecture:** The ledger is a stdlib `http.server` app (`ledger/app.py`) rendering HTML strings; `app.py` reads config at import, so all new logic goes in small importable modules under `ledger/` that tests load directly (pattern: `tests/test_catalog_correct_web.py`). No framework, no build step; JavaScript stays optional (progressive enhancement only).

**Tech Stack:** Python 3, psycopg 3, requests, plain HTML/CSS (`ledger/preserve_theme.css`), pytest run in the ingest-worker image (CI job `pytest`).

**Spec:** the UX review in this conversation (2026-11-06), summarised as phases below. Phases 1–2 are implemented on branch `ledger-ux-item-page`; phases 3–5 are follow-up PRs.

## Phases and effort

| Phase | What | Effort | PR |
|---|---|---|---|
| 1 | Action feedback + confirmations (visibility flash, quarantine confirm step, busy buttons, open-redirect fix) | ~0.5 day | this |
| 2 | Per-item page `/item?key=…`; table rows link to it; mutating actions move off the table rows | ~1 day | this |
| 3 | Clickable status/flag chips + `status` filter on `/` and `/health`; health attention "showing N of M" | ~0.5 day | next |
| 4 | Readable timestamps (`fmt_ts`) and status badges in all tables; truncated error cells | ~0.5 day | next |
| 5 | Correction form: prefill current Omeka values, keep/set/clear per field, before/after diff before applying | ~1.5 days | later |
| later | `/ops` running/queued jobs, `/logs` tail view, page jump in pagination, `aria-sort` on `<th>`, light theme | small each | later |

## Global Constraints

- No new Python dependencies (image installs only `psycopg[binary] pyyaml requests boto3`).
- Pages must work with JavaScript disabled; JS only adds confirm dialogs and busy states.
- Omeka writes: visibility keeps its `o:is_public`-only PATCH (safe per the full-item rule: bodies with only `o:` keys leave values alone). Phase 2 adds **reads only** (GET item).
- Every user-supplied string rendered into HTML goes through `html.escape`.
- Redirect targets must be local paths: start with `/`, not `//`.
- Copy follows the archivist guide's plain-language style (no SQL/column names in sentences a non-admin reads; raw field names are fine in the "All fields" table).

## Review Focus

1. **Omeka unreachable or creds missing** when the item page loads → page still renders, visibility shows "Unknown", both Publish and Hide offered. (test in Task 3)
2. **`game_key` with spaces, slashes, `&`, unicode** → item links are URL-encoded and the lookup finds the row. (test in Task 3)
3. **Row without `omeka_item_id`** (not in Omeka yet) → item page renders, no visibility/correct/quarantine actions, says why. (test in Task 3)
4. **Visibility script fails** (bad id, Omeka 500) → user lands back where they were with a red notice carrying the script's last error line, not a silent redirect. (test in Task 1)
5. **`return_to=//evil.example`** or a missing/odd Referer → redirect falls back to `/`. (test in Task 1)

### Task 1: Notices after redirect + visibility outcome

**Files:**
- Create: `ledger/notice.py`
- Modify: `ledger/site_ui.py` (render notice under `<h1>`, busy-button script), `ledger/app.py` (`/visibility` POST, `do_GET` sets notice), `ledger/preserve_theme.css` (`.notice`, `.notice-ok`, `.notice-fail`)
- Test: `tests/test_ledger_notice.py`

**Interfaces:**
- Produces:
  - `safe_return_path(return_to: str, referer: str) -> str` — `return_to` if local, else Referer's path if local, else `/`.
  - `with_notice(path: str, kind: str, message: str) -> str` — appends `notice=<kind>&msg=<message>` to `path` (keeping its query); `kind` ∈ `{"ok","fail"}`; message truncated to 300 chars.
  - `render_notice(qs: dict[str, list[str]]) -> str` — escaped `<div class="notice notice-ok|notice-fail" role="status">…</div>` or `""` for unknown kind/empty.
  - `visibility_message(item_ref: str, is_public: bool, code: int, output: str) -> tuple[str, str]` — `("ok", "Item 1234 is now public.")` / `("ok", "Item 1234 is now private.")` / `("fail", "Couldn't publish item 1234: <last non-empty output line>")` (`hide` for private).
  - `site_ui.set_current_notice(html: str)` (thread-local, same pattern as `set_current_user`).

- [ ] **Step 1: Failing tests** — `safe_return_path("//evil.example/x", "") == "/"`, `safe_return_path("/item?key=a", "") == "/item?key=a"`, `safe_return_path("", "https://ledger.hitsave.org/health?sort=x") == "/health"`; `with_notice("/item?key=a b", "ok", "Done")` parses back to `key=a b`, `notice=ok`, `msg=Done`; `render_notice({"notice":["fail"],"msg":["<b>x"]})` contains `&lt;b&gt;x` and `notice-fail`; `render_notice({"notice":["weird"]}) == ""`; `visibility_message("1234", True, 1, "Traceback…\nRuntimeError: PATCH items 1234 visibility failed (500)\n")[1].endswith("PATCH items 1234 visibility failed (500)")`.
- [ ] **Step 2:** run `pytest tests/test_ledger_notice.py -q` → FAIL (module missing).
- [ ] **Step 3:** implement `ledger/notice.py`; `/visibility` POST uses `run_visibility`'s `(code, output)`, audits `code`, redirects 303 to `with_notice(safe_return_path(...), *visibility_message(...))`; missing `omeka_ref` → fail notice "No Omeka item given.". `do_GET` calls `set_current_notice(render_notice(parse_qs(parsed.query)))` before dispatch. Shell prints the notice after `<h1>`.
- [ ] **Step 4:** busy buttons: shell adds one inline `<script>`: on `submit` (skip if `e.defaultPrevented`), find `button[data-busy]` in the form; if already disabled `preventDefault()`, else on next tick disable it and set its text to `data-busy`. Correct, quarantine and visibility submit buttons get `data-busy="Running…"`.
- [ ] **Step 5:** run tests → PASS; commit `ledger/notice.py ledger/site_ui.py ledger/app.py ledger/preserve_theme.css tests/test_ledger_notice.py`.

### Task 3: Per-item page

**Files:**
- Create: `ledger/item_page.py`, `ledger/omeka_status.py`, `ledger/formatting.py`
- Modify: `ledger/app.py` (route `/item`), `ledger/preserve_theme.css` (`.kv`, `.status-badge`, `.actions-row`, `.btn-danger`)
- Test: `tests/test_ledger_item_page.py`

**Interfaces:**
- Produces:
  - `formatting.fmt_ts(value) -> str` — `datetime` → `"2026-11-06 12:34 UTC"` (converted to UTC; naive treated as UTC), `None` → `"—"`, other → `str(value)`. (Phase 4 reuses it.)
  - `formatting.item_href(game_key: str) -> str` — `"/item?" + urlencode({"key": game_key})`.
  - `omeka_status.fetch_item_is_public(item_id: int, *, get=requests.get, config_root: Path = Path(os.environ.get("HITSAVE_CONFIG_ROOT","/config"))) -> bool | None` — GET `<api.base_url>/items/<id>` with key_identity/key_credential (same config/cred resolution as `scripts/set-omeka-visibility.py`, timeout 5 s); returns `o:is_public`, or `None` on any error (missing config, network, non-200, bad JSON).
  - `item_page.fetch_item(connect, game_key: str) -> dict | None` — `SELECT * FROM game_ingest WHERE game_key = %s`, dict in column order.
  - `item_page.render_item_page(row: dict, *, admin_base: str, site_base: str, is_public: bool | None, status_config: dict) -> bytes` and `render_item_not_found(game_key: str, *, status_config: dict) -> bytes` (404).
- Page content, top to bottom: title (`moby_title` or `game_key`), game key in `<code>`; status badge; **Catalog record** panel: if no `omeka_item_id` → "Not in the catalog yet; actions appear once it has an Omeka record." Else visibility line (Public / Private / Unknown — couldn't reach Omeka), links admin ↗, public page ↗, **Correct metadata** (`/correct?omeka_ref=`), and visibility buttons: Public → Hide only, Private → Publish only, Unknown → both; forms post to `/visibility` with `return_to=item_href(key)`, `onsubmit="return confirm('…')"` and `data-busy`. **Quarantine** link (danger style) unless status is already `quarantine`, in which case show the block reason. **Problems** panel only when `error_message` or `block_reason`: full error in `<pre>`. **All fields**: `<table class="kv">` of every column, `fmt_ts` for datetimes, `—` for None, dict/list as `json.dumps(indent=2)` in `<pre>`.

- [ ] **Step 1: Failing tests** — `fmt_ts(datetime(2026,11,6,13,34,tzinfo=timezone(timedelta(hours=1)))) == "2026-11-06 12:34 UTC"`, `fmt_ts(None) == "—"`; `item_href("a b&c/ü")` round-trips via `parse_qs`; `fetch_item_is_public` with a stub `get` returning 200 `{"o:is_public": False}` → `False`, raising → `None`, missing config dir → `None`; render with `is_public=True` contains Hide form and no Publish form, `False` the reverse, `None` both; row without `omeka_item_id` contains "Not in the catalog yet" and no `/visibility` form; `status="quarantine"` hides the Quarantine link; `error_message="<x>"` appears escaped in `<pre>`; not-found page contains the escaped key.
- [ ] **Step 2:** run → FAIL.
- [ ] **Step 3:** implement modules; `/item` GET in `app.py`: read `key`, `fetch_item`, `fetch_item_is_public` only when `omeka_item_id` is set, send 200 / 404.
- [ ] **Step 4:** run → PASS; commit.
